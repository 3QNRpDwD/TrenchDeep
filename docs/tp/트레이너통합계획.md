# PreparedTrainer와 Trainer API 통합

## 목표와 확정 사항

4개 배치 학습 패러다임을 `Trainer<Eager>`와 `Trainer<Prepared>`의 동일한 학습 API로 통합한다. 공통 모델 trait과 선택적 prepared 지원 trait을 사용하고, 실행 방식은 타입으로 명시한다.

- Breaking change를 허용하며 저장소의 활성 호출부를 함께 전환한다.
- eager를 기본 실행 방식으로 한다. prepared 미지원 모델은 컴파일 단계에서 거부하며 자동 fallback은 제공하지 않는다.
- RL 학습 구조와 완전한 checkpoint resume 구현은 이번 범위에서 제외한다.
- 이미 공유 중인 `TrainingService`의 학습 루프·메트릭·옵저버·체크포인트 처리를 재사용한다.

## 공개 API 설계

### Trainer 생성과 실행

`Trainer<Mode = Eager>`가 실행 context와 공통 학습 설정을 소유한다. 기존의 설정용 `Trainer`와 실행용 Trainer 분리를 없앤다.

```rust
let trainer = Trainer::builder(&ctx)
    .seed(42)
    .build(); // Trainer<Eager>

trainer.fit(&mut model, &mut optimizer, input, schedule)?;

let trainer = Trainer::minimal(&ctx).prepared(); // Trainer<Prepared>
trainer.fit(&mut model, &mut optimizer, input, schedule)?;
```

- `new(&ctx)`는 기존 개별 Trainer처럼 silent 설정을 사용한다. `silent/minimal/default/verbose`는 기존 프리셋 값을 보존한다.
- `.prepared(self)`는 context·설정·hook·observer를 보존하며 실행 타입만 전환한다.
- 양쪽 타입에 `with_seed`, `with_hook`, `with_observer`, `check_finite_gradients`, `with_max_grad_norm`, `with_ramp`를 동일하게 제공한다.
- `fit(&self, model, optimizer, input, schedule)`와 `fit_checkpointed(...)`의 인자 순서와 `TrainResult`를 유지한다. 후자는 `CheckpointableModel`을 추가로 요구한다.
- `PreparedTrainer`, 4개 패러다임별 Trainer, `fit_loader` 별칭과 배치 학습용 미구현 `resume` API를 제거한다. 호환 어댑터는 두지 않는다.

### 모델 계약

공통 `TrainingModel: TrainableModel`을 도입한다.

- `type Batch: BatchInputs`와 `const PARADIGM: &'static str`를 정의한다.
- `forward_batch(&mut self, batch: &Self::Batch, step: &TrainingStepContext) -> MlResult<TrainingOutput>`을 eager 학습 계약으로 사용한다.
- `TrainingOutput`은 현재 내부 `StepData`의 loss·prediction·target·weight·tokens·lambda를 담는다. 기존 패러다임별 가중치 계산과 메트릭 의미를 보존한다.
- `TrainingStepContext`는 0부터 시작하는 epoch·batch 인덱스와 준지도 학습용 `Option<f32>` lambda를 제공한다. 옵저버의 기존 1부터 시작하는 번호는 유지한다.
- `PreparedModel`은 `TrainingModel`을 상속한다. 중복된 `Batch`와 `PARADIGM` 선언을 제거하고, `execution_batch`가 동일한 `TrainingStepContext`를 받게 한다. `forward_inputs`와 직접 executor 실행 API는 유지한다.
- 기존 4개 패러다임별 모델 trait 구현을 `TrainingModel`로 전환한다. prepared 모델은 eager 구현과 입력 기반 연산을 내부 helper로 공유해 수식 중복을 피한다.

## 내부 구현과 전환

- `TrainingService`를 context·core·공통 옵션에서 생성하도록 변경하고, `Trainer` 전체를 생성 인자로 받는 의존성을 제거한다.
- 공통 설정 메서드는 `impl<Mode> Trainer<Mode>`에 모은다. 실행 타입별 구현은 batch 실행 전략만 선택하며 epoch 루프와 `finish_step`을 공유한다.
- eager는 loader → forward → backward → optimizer를 기존 training scope 안에서 실행한다. loader가 생성한 계산 그래프의 역전파 연결을 보존한다.
- prepared는 입력 준비를 캡처 밖에서 수행하고, 입력 signature와 variant별 executor를 한 번의 `fit` 동안 캐시한다. epoch 간 재사용하고 `fit` 종료 시 폐기한다.
- 준지도 lambda는 기존 `ConsistencyRamp`로 계산해 두 경로에 동일하게 전달한다. prepared에서는 변하는 lambda를 입력 텐서로 전달하여 첫 epoch 값이 캡처에 고정되지 않게 한다.
- context·optimizer parameter 검증, 실패 시 graph/gradient 정리, 체크포인트 저장 조건과 옵저버 호출 순서를 보존한다.
- 활성 모델·테스트·예제·벤치마크를 새 API로 전환하고 migration 문서를 추가한다. 직접 `PreparedModelExecutor`를 사용하는 호출부도 새 모델 계약에 맞춘다.
- RLTrainer의 공개 API와 동작은 유지하고 서비스 생성 변경만 반영한다. legacy benchmark 전용 구현은 통합 대상에서 제외한다.

## 검증과 완료 기준

- **타입 계약:** eager 전용 모델은 `Trainer<Eager>`에서 컴파일되고, `Trainer<Prepared>`에서는 실패하는 compile-fail doctest를 추가한다.
- **동작 동등성:** 4개 패러다임의 loss·파라미터 업데이트·핵심 메트릭을 검증한다. 양쪽 실행을 지원하는 모델은 동일 입력과 seed에서 eager/prepared 결과를 비교하며 실행 시간은 비교에서 제외한다.
- **Prepared 재사용:** 동일 signature 재사용, 마지막 작은 배치, variant 변경, 여러 epoch, 별도 `fit` 호출 간 캐시 분리를 확인한다.
- **준지도 학습:** epoch마다 lambda가 바뀌고 실제 loss·gradient에 반영되는지 양쪽 경로에서 확인한다.
- **회귀:** loader가 만든 그래프의 gradient, 오류 후 정리, context 불일치, optimizer parameter 불일치, clipping·NaN 검사, hook·observer와 checkpoint 저장을 확인한다.
- `cargo test --features enableBackward`, doctest, `cargo check --all-targets --all-features`를 실행한다. 기존 diffusion eager/prepared 동등성 테스트와 RL 회귀 테스트도 통과해야 한다.

현재 작업 트리의 prepared runtime 변경과 문서 삭제는 기존 사용자 작업으로 보존한다. 이번 계획 수립에서는 파일을 변경하거나 테스트를 실행하지 않았다.
